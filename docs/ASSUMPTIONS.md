# Допущения, открытые вопросы и ограничения MVP

## Значения по умолчанию для неопределённых бизнес-правил

| Открытый вопрос из ТЗ | Принятое в MVP решение | Где меняется |
|---|---|---|
| Календарные или рабочие дни? | По умолчанию рабочие дни (Пн–Пт, без праздников РФ 2026). Режим выбирается на уровне проекта | Настройки → «Режим таймера»; карточка проекта |
| Способ юридически значимого подписания | Простая ЭП: чекбокс и одноразовый код на почту; фиксируются дата, IP, user-agent, редакция и контрольная сумма. Требуется соглашение об ЭП в договоре (есть в шаблоне) | `services/contracts.ts`; `SignMethod.EXTERNAL_EDO` для ЭДО |
| Оплата обычных проектов через сайт? | Эквайринг используется только для быстрых заказов; обычные проекты оплачиваются по счёту | `services/payments.ts` — можно добавить оплату этапов |
| Размеры и форматы файлов | До 50 МБ на файл (настройка); форматы из ТЗ. SVG и TXT запрещены для загрузки пользователем | Настройки; `domain/files.ts` |
| Состав ТЗ по типам конструкций | Единый набор полей из ТЗ; для быстрого заказа — свои параметры (габариты, кровля, каркас, фундамент, снеговой район) | `domain/spec.ts`, `domain/quick-order.ts` |
| CAD/BIM-форматы AI | Демо-пакет: SVG, IFC4 (упрощённый), PDF, CSV | `lib/ai/package-builder.ts` |
| Несколько сотрудников у заказчика-организации | Один пользователь — один заказчик; `Company` хранит реквизиты. Многопользовательские организации — следующий этап | Схема `Company`/`User` |
| Несколько проектировщиков в проекте | Да: команда из любого числа проектировщиков, каждый может вести этапы | Карточка проекта → «Назначить команду» |
| Шаблоны договора и КП | Демонстрационные тексты (`prisma/templates.ts`) — **нужна юридическая проверка** | Настройки → Шаблоны |
| Кто меняет договорные сроки | Руководитель проекта (своего) и директор, с обязательным основанием и записью в журнал | `services/timer.ts → updateDeadline` |
| Интеграции 1С, CRM, ЭДО, Telegram | Не подключены; есть CSV-выгрузки и точки расширения | ARCHITECTURE.md |
| Публикация портфолио | Фото не публикуются; показаны схемы-заглушки и описания с действующего сайта | CONTENT_REQUESTS.md |

Другие допущения:
- Регион компании — Липецк (группа ВК evotech48); реквизиты (ИНН, адрес) — заглушки.
- Цены калькулятора и быстрых заказов демонстрационные: `domain/quick-order.ts`.
- Веса этапов для процента готовности: ТЗ 10%, эскиз 15%, модель 25%, чертежи 30%, документация 10%, передача 10%.
- Автоматическая пауза таймера ставится, если открыт запрос с флагом «остановить таймер» или этап находится на согласовании у заказчика.
- Порог предупреждения о сроке: 15% срока, но не меньше двух дней.
- Заявка с сайта с той же почтой, что и у зарегистрированного заказчика, привязывается к его кабинету. При формировании договора заказчик без кабинета получает приглашение.
- В воронке разрешены переходы вперёд и назад; «Отказ» — с обязательной причиной; «Договор заключён» — только через создание проекта при подписанном договоре.

## Ограничения MVP

- AI работает в демо-режиме: варианты и документация не предназначены для строительства. Claude API подключается переменной окружения (заготовка готова).
- Т-Банк проверен на демо-банке и тестах подписи; реальный тестовый терминал требует ключей и публичного URL для уведомлений.
- S3, антивирус и ЭДО — интерфейсы без боевых реализаций.
- PDF строятся из текста шаблона, без сложной вёрстки и печатей.
- Нет полнотекстового поиска по файлам и комментариям, нет drag-and-drop в канбане (статус меняется кнопкой).
- 2FA подготовлена в схеме, но не включена в интерфейсе.
- Уведомления — только внутренние и почта; Telegram и SMS не подключены.
- Страница чужого объекта возвращает экран 404, но HTTP-статус 200 (из-за стриминга с `loading.tsx`); данные при этом не раскрываются.

## Следующие шаги до production

1. Юридическая проверка шаблонов договора, политики и согласия; реальные реквизиты.
2. Тестовый терминал Т-Банка, затем боевой; публичный `NotificationURL`; чек 54-ФЗ (параметр `Receipt`).
3. S3-хранилище (Yandex Object Storage) и ClamAV.
4. Хостинг в РФ (152-ФЗ), managed PostgreSQL с бэкапами, HTTPS, мониторинг (`/api/health`), сбор логов.
5. Подключение Claude API, оценка качества на эталонных заказах, затем CAD/BIM-генерация (этап 3).
6. Контент: фотографии портфолио с подтверждёнными правами, отзывы, реальные цены.
7. E2E-тесты в браузере (Playwright) поверх существующих интеграционных.
8. 2FA для сотрудников, Telegram-уведомления, ЭДО, интеграции с 1С и CRM.
