## 1. Общие сведения

### 1.1. Назначение

Платформа ЭвоТех — сайт и рабочая система проектной организации по металлоконструкциям. Она закрывает весь путь заказа:

```
Заявка → техническое задание → коммерческое предложение → договор (подписание кодом)
→ проект: эскиз → 3D-модель → чертежи → документация → передача → архив
```

Отдельный поток — **быстрый заказ** малых конструкций (навесы, гаражи, террасы, беседки, ангары): варианты эскиза генерирует AI, затем договор, оплата и архив документации.

## 2. Роли пользователей

Пять ролей. Права проверяются на сервере: сначала разрешение роли, затем доступ к конкретному объекту. Полная матрица — в [RBAC.md](RBAC.md).

| Роль | Код | Назначение | Видит |
|---|---|---|---|
| Директор | `DIRECTOR` | Полный доступ: пользователи, настройки, шаблоны, журнал, аналитика, финансы | Всё |
| Руководитель проектов | `PROJECT_MANAGER` | Ведёт проект от подписанного договора до сдачи: команда, сроки, этапы, утверждение ТЗ | Все проекты и заявки; управляет проектами, где он РП |
| Менеджер проектов | `SALES_MANAGER` | Заявки, ТЗ, КП, договоры, передача проекта РП | Все заявки; проекты, которые он передал |
| Проектировщик | `DESIGNER` | Результаты этапов: версии, внутренняя проверка | Только назначенные проекты |
| Заказчик | `CUSTOMER` | Заявки, ТЗ, согласование, подписание, оплата, скачивание | Только свои заявки, проекты, заказы |

Правила, общие для всех ролей:
- заказчик не видит внутренние комментарии и файлы, а также версии результатов, ещё не переданные ему на согласование;
- чужой объект открывается как страница «не найдено», без раскрытия данных;
- меню кабинета строится из той же матрицы прав.

### 3.3. Калькулятор предварительного расчёта

Поля: вид работ, масса конструкций (ползунок 1–300 т), сложность (простая / средняя / высокая).

| Вид работ | Ставка, ₽/т |
|---|---|
| КМ | 4 500 |
| КМД | 3 500 |
| КМ + КМД | 7 500 |
| 3D-модель | 2 500 |
| Реверсивный инжиниринг | 6 000 |

Формула (`src/domain/quick-order.ts → estimateProject`):
- коэффициент сложности: 1 / 1,3 / 1,7;
- база = max(20 000; ставка × масса × коэффициент);
- диапазон цены: база × 0,85 … база × 1,2, с округлением до 1 000 ₽;
- срок = ⌈5 + √масса × 2 × коэффициент⌉ … ×1,4 рабочих дней.

Под расчётом — короткая форма заявки: тема и описание подставляются из параметров расчёта, источник заявки — «Калькулятор на сайте». `[РЕДАКЦИЯ: ставки демонстрационные]`

### 3.5. Форма заявки

Поля:
- имя* и почта*;
- телефон;
- компания и тип объекта (в полной форме);
- «что нужно спроектировать»*;
- подробности;
- согласие на обработку ПДн* (ссылки на согласие и политику).

Защита и сбор данных:
- антиспам: скрытое поле-ловушка, минимальное время заполнения 2,5 с, не больше 5 заявок с одного IP за 10 минут;
- UTM-метки первого визита хранятся в cookie 30 дней и сохраняются в заявке, вместе с источником и referrer;
- источники: форма на сайте / калькулятор / контактная форма / кабинет / быстрый заказ / вручную / телефон / Авито.

Состояния формы: отправка (кнопка заблокирована), ошибка (текст ошибки и ошибки полей, введённые данные сохраняются), успех («Заявка №N принята»). Предложение зарегистрироваться той же почтой.

После отправки:
- заявка сохраняется до любых внешних вызовов;
- назначается наименее загруженный менеджер проектов;
- создаётся черновик ТЗ;
- менеджер получает уведомление и письмо, клиент — письмо-подтверждение.

## 4. Авторизация и учётные записи

| Функция | Описание |
|---|---|
| Регистрация | Только для заказчиков: имя, почта, телефон, организация, пароль (от 8 символов, буквы и цифры), согласие на ПДн. Заявки с этой почтой привязываются автоматически. Письмо для подтверждения почты |
| Вход | Почта и пароль. Не больше 30 попыток с IP и 10 на почту за 15 минут; после 5 неудач — блокировка на 15 минут |
| Подтверждение почты | Ссылка из письма (48 ч), подтверждение кнопкой, а не самой ссылкой: почтовые сканеры не «съедят» токен |
| Восстановление пароля | Ссылка на 2 часа; ответ одинаковый, существует почта или нет; после сброса все сессии завершаются |
| Приглашение | Директор приглашает сотрудников; менеджер при формировании договора автоматически приглашает заказчика. Ссылка действует 7 дней, пользователь сам задаёт пароль |
| Смена пароля | «Профиль → Смена пароля»: текущий и новый пароль, остальные сеансы завершаются |
| Сессия | Случайный токен в httpOnly-cookie `evo_session` на 14 дней; в БД хранится только SHA-256 токена |
| 2FA | Заложено в схеме (`twoFactorEnabled`, `twoFactorSecret`), в интерфейсе не включено |

## 6. Модули личного кабинета

### 6.1. Дашборд (`/cabinet`)

Содержимое зависит от роли:
- **Заказчик:** кнопки «Новая заявка» и «Быстрый заказ»; блок «Требуют вашего внимания» (согласования, запросы с паузой таймера, договоры на подписание); «Мои проекты» (готовность, текущий этап, таймер); «Мои заявки»; «Быстрые заказы».
- **Менеджер проектов:** счётчики (новые, в работе, подготовка ТЗ, договоры на подписании); новые заявки; мои задачи со сроками.
- **Проектировщик:** счётчики этапов (в работе, на проверке, возвращены); список моих этапов; назначенные проекты.
- **Директор и РП:** новые заявки за 30 дней, конверсия, проекты с риском просрочки, сумма оплат; список риска просрочки; очереди (внутренняя проверка, открытые запросы, возвраты); активные проекты.

### 6.2. Заявки — CRM (`/cabinet/leads`)

**Список:**
- поиск по номеру, теме, контакту, почте, компании;
- фильтры: статус, источник, ответственный;
- сортировка: новые / старые / по обновлению / по номеру;
- пагинация по 20;
- выгрузка CSV.

**Канбан:** колонки по статусам воронки и «Отказ»; в карточке источник, дата и ответственный; кнопка перехода на следующий шаг.

**Новая заявка:** сотрудник регистрирует звонок или ручную заявку, заказчик создаёт заявку из кабинета.

**Карточка заявки** (`/cabinet/leads/[id]`):
- данные заказчика, UTM, referrer, статус кабинета заказчика, описание;
- **ТЗ:** статус, версия, кнопка «Открыть ТЗ» или «Создать ТЗ»;
- **коммерческие предложения:** список с PDF; «Отправить заказчику»; у заказчика — «Принять» / «Отклонить»; конструктор КП (позиции, количество, единица, цена, итог, срок, срок действия, примечания);
- **договор:** сумма и срок из последнего КП, предпросмотр по шаблону, «Сформировать и отправить заказчику»; после подписания — «Создать проект и передать РП» с выбором руководителя;
- **файлы:** загрузка по категориям, признак «внутренний»;
- **комментарии:** у сотрудников есть внутренние;
- **управление:** смена статуса (для отказа обязательна причина), назначение ответственного;
- **задачи:** название, срок, отметка выполнения;
- **история статусов:** кто и когда менял.

### 6.3. Техническое задание (`/cabinet/specs`, `/cabinet/specs/[id]`)

Поля ТЗ (`src/domain/spec.ts`, \* — обязательные):

| Группа | Поля |
|---|---|
| Объект | Название объекта\*, тип объекта\* (список), назначение\*, адрес или регион\* |
| Геометрия | Габариты и основные размеры\*, пролёты / высота / этажность |
| Конструкция | Материалы и профили, тип фундамента (список) |
| Условия | Нагрузки и условия эксплуатации, климат (снеговой и ветровой район) |
| Внешний вид | Требования к внешнему виду, покрытие и цвет |
| Результат | Необходимые результаты проектирования\* |
| Сроки и бюджет | Желаемый срок (дата), бюджетный диапазон |
| Прочее | Комментарии |

Функции:
- каждое сохранение с изменениями — новая версия: автор, время, изменённые поля, комментарий;
- «Сохранить и отправить на проверку» — проверяет обязательные поля;
- сотрудник — «Запросить уточнения» (текст уходит заказчику);
- РП или директор — «Утвердить ТЗ». Создаётся неизменяемая версия-снимок, этап «ТЗ» закрывается, этап «Эскиз» запускается;
- история версий с просмотром любой версии;
- вложения: исходные данные, фото, чертежи и схемы.

### 6.4. Проекты (`/cabinet/projects`, `/cabinet/projects/[id]`)

**Список:** поиск (номер, название, заказчик), фильтр по статусу, готовность в процентах, состояние таймера, выгрузка CSV.

**Карточка проекта** — шапка (номер, название, заказчик, ссылка на ТЗ и его статус), общая готовность, баннер «Ожидается ваше согласование» для заказчика, вкладки:

| Вкладка | Содержимое |
|---|---|
| Обзор | Таймер (п. 7.4): остаток, процент использования, причина паузы, старт, договорная и прогнозная даты, паузы. Для РП и директора: запуск таймера, ручная пауза с причиной, возобновление, изменение сроков с основанием. История пауз (удаление записи — только директор). Участники; «Назначить команду» (РП, проектировщики); оплата исполнителям (зарплата и аванс, видна руководителям); договор; статус проекта (в работе / приостановлен / отменён) с причиной |
| Этапы и согласования | Шесть этапов: статус, объект согласования, исполнитель, даты. Для каждого — версии с файлами, связь с предыдущей версией, отметка «Зафиксирована» и проверка целостности, история решений. Доступные действия по роли. Загрузка новой версии: файлы, описание изменений |
| Запросы | Запросы заказчику: текст, этап, флаг «Остановить таймер»; ответ заказчика; отмена запроса |
| Комментарии | Обсуждение с упоминаниями `@Имя Фамилия` (уведомление упомянутому); у сотрудников есть внутренние |
| Файлы | Все файлы проекта по категориям, предпросмотр изображений и PDF, загрузка, удаление (кроме файлов зафиксированных версий); контроль обязательных результатов |
| Варианты (AI) | Генерация вариантов конструкции по утверждённому ТЗ (демо), выбор варианта заказчиком |
| Лента событий | История статусов; для сотрудников — журнал действий по проекту |

Веса этапов для общей готовности:

| Этап | Вес |
|---|---|
| ТЗ | 10% |
| Эскиз | 15% |
| 3D-модель | 25% |
| Чертежи | 30% |
| Документация | 10% |
| Передача | 10% |

Доля внутри этапа: не начат 0; в работе 0,3; возвращён 0,4; внутренняя проверка 0,6; у заказчика 0,75; согласован 0,9; завершён 1.

### 6.5. Согласования (`/cabinet/approvals`)

- Список «Ожидают решения»: этапы на внутренней проверке, у заказчика, возвращённые; ТЗ на проверке (для утверждающих). Заказчик видит только объекты на своём согласовании.
- «История решений»: дата, проект и этап, решение, кто принял, комментарий.

### 6.6. Сообщения и запросы (`/cabinet/requests`)

Все запросы заказчикам по доступным проектам: статус, дата, влияние на таймер («на паузе», «пауза снята», «не влияет»).

### 6.7. Файлы и версии (`/cabinet/files`)

- Все доступные файлы, кроме итоговых архивов: поиск по имени, фильтр по категории.
- Скачивание по временной ссылке, предпросмотр изображений и PDF.
- Категории: исходные данные, фотографии, эскиз, 3D-модель, чертежи, спецификации и ведомости, документы, договор, архив, прочее.

### 6.8. Коммерческие предложения (`/cabinet/offers`)

Реестр КП: номер и версия, заявка, сумма, срок, дата окончания действия, статус (черновик / отправлено / принято / отклонено), PDF.

### 6.9. Договоры (`/cabinet/contracts`, `/cabinet/contracts/[id]`)

**Реестр:** номер, основание (заявка, проект, быстрый заказ), заказчик, сумма, статус, редакция, дата подписания.

**Карточка договора:**
- текст выбранной редакции и её контрольная сумма;
- PDF редакции (с отметкой о подписании);
- список редакций с отметкой о подписании;
- **подписание (заказчик):** «Получить код» — код на почту, действует 10 минут, не чаще раза в минуту, до 5 попыток ввода; галочка согласия; ввод кода; фиксируются дата, IP, user-agent, редакция и контрольная сумма;
- **корректировка (менеджер):** сумма, срок, текст новой редакции; ранее выданные коды перестают действовать; подписанный договор изменить нельзя;
- «Аннулировать» — с подтверждением.

### 6.10. Платежи (`/cabinet/payments`)

- История: дата, назначение, сумма, статус, ID платежа в банке, режим (тестовый или боевой).
- У директора — кнопка «Возврат».
- Данные карт не хранятся.

### 6.11. Быстрые заказы (`/cabinet/quick-orders`)

**Мастер нового заказа** (`/new`), пять шагов:
1. **Тип конструкции.**
2. **Габариты:** длина, ширина, высота, площадь; подсказка с лимитами.
3. **Конструкция:** кровля (односкатная, двускатная, арочная, плоская), покрытие (профнастил, поликарбонат, металлочерепица, сэндвич-панели), каркас (профтруба, двутавр/швеллер, комбинированный), фундамент (винтовые сваи, плита, столбчатый, существующее основание), примыкание к зданию, ворота.
4. **Участок:** регион\*, снеговой район I–V, цвет RAL, пожелания, фото участка.
5. **Проверка** и «Сформировать варианты эскиза».

Сбоку — ориентировочная стоимость и пометка о демо-режиме.

| Тип | Макс. Д×Ш×В, м | Ставка, ₽/м² | Минимум, ₽ |
|---|---|---|---|
| Навес | 30 × 15 × 6 | 450 | 15 000 |
| Гараж | 15 × 12 × 5 | 600 | 25 000 |
| Терраса | 20 × 10 × 4 | 500 | 18 000 |
| Беседка | 8 × 8 × 4,5 | 900 | 20 000 |
| Ангар / склад | 60 × 24 × 10 | 350 | 40 000 |

Наценки: снеговой район IV–V +15%, примыкание к зданию +10%, комбинированный каркас +10%, ворота +5 000 ₽, плюс надбавка выбранного варианта. Цена округляется до 500 ₽. `[РЕДАКЦИЯ: цены демонстрационные]`

**Карточка заказа** (`/[id]`):
- шкала этапов: генерация → выбор → договор → оплата → документация → готово;
- AI-задача: статус, «Повторить запуск» при ошибке;
- три варианта эскиза: SVG с фасадом, разрезом, планом и штампом; описание; цена; «Выбрать»;
- договор-оферта с подписанием кодом;
- оплата: кнопка неактивна, пока договор не подписан, и показывает причину;
- итоговый архив: доступен при выполнении трёх условий, они показаны списком;

Состав архива:
- `README.txt`;
- `01_Эскизы` (SVG), `02_Визуализации` (SVG);
- `03_3D-модель` (IFC4: колонны и балки);
- `04_Чертежи` (PDF);
- `05_Спецификации` (CSV), `06_Ведомости` (расход стали, CSV);

## 7. Бизнес-процессы и статусы

### 7.1. Воронка заявок

`new` (новая) → `qualification` (квалификация) → `tz_preparation` (подготовка ТЗ) → `commercial_offer` (КП) → `contract_approval` (согласование договора) → `awaiting_signature` (ожидает подписания) → `won` (договор заключён)

Правила:
- переходы вперёд и назад между рабочими статусами разрешены;
- `lost` (отказ) — из любого незавершённого статуса, причина обязательна; из отказа заявку можно вернуть только в «Новую»;
- `won` — только через «Создать проект» при подписанном договоре;
- формирование КП переводит заявку в «КП», формирование договора — в «Ожидает подписания».

### 7.2. Техническое задание

`DRAFT` (черновик) → `SUBMITTED` (на проверке) → `CLARIFICATION` (уточнения) ↔ `SUBMITTED` → `APPROVED` (утверждено, снимок неизменяем)

### 7.3. Этапы и версии результата

Этапы: `brief` ТЗ → `sketch` эскиз → `model` 3D-модель → `drawings` чертежи → `documentation` документация → `delivery` передача.

| Действие | Из статуса | В статус | Кто | Комментарий |
|---|---|---|---|---|
| Начать этап | не начат | в работе | Проектировщик, РП | Предыдущий этап должен быть завершён |
| Загрузить версию | в работе / возвращён | в работе | Проектировщик, РП | Описание и файлы обязательны |
| На внутреннюю проверку | в работе | внутренняя проверка | Проектировщик, РП | Нужна новая версия |
| Подтвердить проверку и отправить заказчику | внутренняя проверка | у заказчика | Проектировщик, РП | — |
| Вернуть на доработку (внутр.) | внутренняя проверка | в работе | Проектировщик, РП | Обязателен |
| Согласовать | у заказчика | согласован | Заказчик | — |
| Вернуть с замечаниями | у заказчика | возвращён | Заказчик | Обязателен |
| Завершить этап | согласован | завершён | Проектировщик, РП | Запускается следующий этап; после последнего проект завершается, таймер останавливается |

При согласовании версия **фиксируется**: сохраняются время и контрольная сумма описания и файлов. Подмену файлов после согласования видно в интерфейсе. Новая версия создаётся отдельно и ссылается на предыдущую. Этап «ТЗ» закрывается только утверждением ТЗ.

### 7.4. Таймер срока

- **Старт** — дата подписания договора (или ручной запуск). **Срок** — договорной, в рабочих днях (Пн–Пт без праздников, по Москве) или в календарных.
- **Автопауза** открывается, когда есть открытый запрос с флагом «Остановить таймер» или этап у заказчика на согласовании. Закрывается, когда таких ожиданий не осталось.
- **Ручная пауза** — РП или директор, с обязательной причиной.
- Каждая пауза хранит начало, конец, причину, тип (авто или ручная), инициатора, кто возобновил и комментарий.
- **Состояния:** не запущен, идёт отсчёт, пауза (ждём заказчика), завершён, просрочен.
- **Предупреждение** — остаток не больше max(2 дня; 15% срока). Уведомление шлёт воркер, один раз.
- **Прогноз сдачи** считается от текущего момента плюс оставшееся расчётное время; договорная дата не меняется.
- Изменить сроки может РП или директор, с основанием; это пишется в журнал. Удалить запись о паузе может только директор, с основанием и записью в журнал.

### 7.5. Договор и подписание

`DRAFT` → `AWAITING_SIGNATURE` (ожидает подписания) → `SIGNED` (подписан) | `CANCELLED` (аннулирован)

- Способ подписания — простая ЭП: согласие плюс одноразовый код из письма.
- Подтверждение привязано к конкретной редакции. Новая редакция требует нового подписания.

### 7.6. Быстрый заказ и AI-задача

Статусы заказа: `GENERATING` (генерация вариантов) → `AWAITING_SELECTION` (выбор варианта) → `CONTRACT` (договор) → `AWAITING_PAYMENT` (ожидает оплаты) → `PAID` (оплачен) → `PROCESSING` (документация) → `COMPLETED` (готов) | `CANCELLED` (отменён).

Статусы AI-задачи: `draft` → `queued` → `processing` → `awaiting_selection` → `selected` → `generating_package` → `completed` | `failed`. Повторный запуск продолжает с фазы, на которой произошла ошибка.

### 7.7. Правила доступа к оплате и архиву

- **Оплата** доступна, если договор подписан, подписана **актуальная** редакция и заказ ещё не оплачен.
- **Архив** доступен владельцу заказа или сотруднику, если договор подписан, оплата прошла и AI-задача в статусе `completed`. Ссылка на файл временная.

### 7.8. Платёж

`pending` (ожидает) → `authorized` → `paid` (оплачен) | `cancelled` | `failed` | `refunded`

Финальный статус не откатывается запоздалым уведомлением. Из `paid` возможен только `refunded`.

## 10. API и фоновые задачи

### 10.1. HTTP-маршруты

| Маршрут | Назначение | Защита |
|---|---|---|
| `POST /api/files` | Загрузка файлов (multipart, до 20 за раз) | Сессия, Origin, права на объект, формат, размер, антивирус |
| `GET /api/files/:id/link` | Проверка прав и редирект на временную ссылку | Сессия, права на файл |
| `GET /api/files/dl/:token` | Потоковое скачивание (HMAC-подпись, 5 минут) | Подпись, срок; запись в журнал |
| `GET /api/quick-orders/:id/archive` | Итоговый архив | Правила п. 7.7 |
| `GET /api/contracts/:id/pdf` | PDF редакции договора | Владелец или сотрудник с правами |
| `GET /api/offers/:id/pdf` | PDF коммерческого предложения | Менеджер; заказчик — если КП отправлено |
| `GET /api/export/leads`, `/projects` | CSV-выгрузки | Право выгрузки |
| `GET /api/export/me` | Свои ПДн в JSON | Сессия |
| `GET /api/jobs/:id` | Статус AI-задачи | Владелец или сотрудник |
| `POST /api/payments/tbank/webhook` | Уведомления банка | Token, сумма, идемпотентность |
| `GET /api/health` | Проверка приложения и БД | — |

Остальные изменения данных идут через server actions (`src/app/actions/public.ts`, `src/app/actions/cabinet.ts`).

### 10.2. Воркер (`scripts/worker.ts`, раз в 5 секунд)

- обработка AI-задач, в том числе зависших дольше 10 минут;
- повторная отправка писем: до 5 попыток;
- раз в 5 минут — пересчёт состояний таймеров и предупреждения о сроках.

### 10.3. Скрипты

| Команда | Назначение |
|---|---|

## 11. Безопасность и персональные данные

| Требование | Реализация |
|---|---|
| Проверка прав на сервере | Каждое действие проверяет роль, сервис — доступ к объекту |
| Изоляция заказчиков | Фильтры выборок по роли; чужой объект — страница «не найдено» |
| Пароли | bcrypt (12 раундов), ограничение попыток, временная блокировка |
| CSRF | Проверка Origin (server actions, API загрузки), cookie SameSite=Lax |
| XSS и SQL-инъекции | Экранирование React; параметризованные запросы Prisma |
| Файлы | Белый список форматов, лимит размера, антивирус (интерфейс), временные подписанные ссылки, журнал скачиваний, `Content-Disposition` и CSP |
| Платежи | Проверка подписи (SHA-256, сравнение за постоянное время), сверка суммы, идемпотентность; карты не хранятся |
| Логи | JSON; пароли, токены, почта и телефоны маскируются |
| Журнал | Вход, договоры, платежи, файлы, таймер, статусы, настройки, ПДн |
| ПДн (152-ФЗ) | Сервер в России; выгрузка своих данных; обезличивание директором; выгрузки таблиц с ПДн — вне git |
| Сервер | Файрвол (22/80/443), SSH только по ключу, fail2ban, автоматические обновления безопасности, HSTS |

Допустимые форматы файлов: PDF, DOCX, XLSX, ZIP, 7Z, RAR, JPG, PNG, DWG, DXF, IFC, STEP, STP, RVT. Лимит по умолчанию — 500 МБ, настраивается до 2000 МБ.

## 16. Допущения, ограничения, открытые вопросы

### 16.1. Ограничения текущей версии

- AI работает в демо-режиме: эскизы и документация не для строительства.
- Оплата — демо-банк. **До подключения Т-Банка не давать клиентам ссылку на быстрый заказ.**
- Почта не отправляется, нет SMTP. Почты на домене нет (нет MX-записей), поэтому `info@evotechnology.su` письма не принимает.
- Файлы хранятся на диске сервера, пока не подключено Облако Mail.ru.
- Логины сотрудников вида `…@evotech.local` — временные, нужны реальные адреса почты.
- PDF простые, без печатей и сложной вёрстки. Нет drag-and-drop в канбане. 2FA не включена.
- Страница чужого объекта отдаёт HTTP 200 с экраном «не найдено» (особенность стриминга).

### 16.2. Решения, принятые по умолчанию

Подробно — в [ASSUMPTIONS.md](ASSUMPTIONS.md):
- рабочие дни для таймера;
- простая ЭП;
- эквайринг только для быстрых заказов;
- 500 МБ на файл;
- единые поля ТЗ;
- один пользователь — один заказчик;
- сроки меняют РП и директор.

### 16.3. Требуется от компании `[РЕДАКЦИЯ]`

1. Доступ к REG.RU: перенос DNS, продление домена до 18.12.2026.
2. Почтовый ящик на домене и доступ SMTP.
3. Тариф Облака Mail.ru с WebDAV и пароль приложения.
4. Ключи терминала Т-Банка (сначала тестового) и данные для чеков 54-ФЗ.
5. Реальные почты сотрудников и исполнителей.
6. Реквизиты компании; юридическая проверка договора, оферты, политики и согласия.
7. Фото объектов с правами на публикацию, согласие клиентов на упоминание, отзывы, цифры.
8. Утверждённые цены (калькулятор, быстрые заказы) и шаблоны документов.
9. Ключ Claude API — для перехода от демо-генерации.

### 16.4. Дальнейшее развитие

- Подключить Claude API и CAD/BIM-генерацию документации (Tekla Open API, IfcOpenShell).
- Включить 2FA для сотрудников, уведомления в Telegram.
- Подключить ЭДО, интеграцию с 1С и CRM.
- Добавить E2E-тесты в браузере (Playwright) и мониторинг.
